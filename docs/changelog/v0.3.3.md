# v0.3.3 (2026-11-21)

## Added

### UUIDでのメディア取得API (#62 / TASK-100)

- `KijukuDB::get_media_by_uuid` / `getMediaByUuid`（Rust/TS両SDK・全バックエンド）、`KijukuBackend` trait、RemoteKijukuDB（stdin操作 `getMediaByUuid`）、Web GUI `GET /api/media/uuid/:uuid`、`GET /api/media` の `uuid` クエリパラメータ
- `MediaFilter` に `uuid`（完全一致）・`uuid_in`（IN句）を追加（Rust/TS両SDK）

### bulk_load（export/移行）のローカル→ローカル統合テスト (#64)

- `rust-sdk/tests/bulk_load_test.rs` を追加。`transfer` / `verify` を通常の `cargo test` で検証できるようにした（従来は feature `d1-integration` の実 D1 テストのみ）。uuid 保持（`get_media_by_uuid` 契約）・タグ名集合・属性・ハッシュ・`chunk_size=1` ページング境界・verify の不一致検出・空でない dest への再転送拒否をカバー

## Changed

- rust-sdk 全体（src 28 + tests 13 の計41ファイル）に cargo fmt を適用し整形を統一 (#64)。rustfmt 再現検証によりトークン単位の変更（識別子・文字列内容・数値・制御構造）がないことを確認済み

## Fixed

- `uuid_in` / `id_in` / `exclude_ids` / `tag_ids` のIN句を `json_each` による1パラメータ化に変更（Rust/TS両SDK）(#62)。従来のチャンク分割はIN句をOR結合して単一ステートメントに全件バインドしており、SQLiteのパラメータ数上限（999）やD1のバインド上限（100）を超えるリストでエラーになる実装だった（レビュー指摘により判明）
