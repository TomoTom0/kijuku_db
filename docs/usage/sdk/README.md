# kijuku-db SDK利用ガイド

kijuku-dbは、メディアメタデータを管理するためのデータベースライブラリです。TypeScriptとRustの2つのSDKを提供しています。

## SDK選択ガイド

### TypeScript SDK

**推奨される用途:**
- Node.js/Bun環境でのアプリケーション開発
- TypeScriptプロジェクトとの統合
- Webアプリケーションのバックエンド
- リモートDB操作が必要な場合（SSH経由）

**特徴:**
- 型安全なAPI
- リモートDB操作対応（SSH経由）
- 自動バックアップ機能
- CLIツール提供（データインポート、検索、Web GUI）

[TypeScript SDKガイド →](./ts/README.md)

### Rust SDK

**推奨される用途:**
- パフォーマンスが重要なアプリケーション
- システムツール開発
- メモリ効率が重要な場合
- スタンドアロンバイナリとしての配布

**特徴:**
- 高速なパフォーマンス
- 安全なメモリ管理
- スタンドアロンバイナリ生成
- CLIツール提供（データインポート、検索、Web GUI）

[Rust SDKガイド →](./rust/README.md)

## 共通コンセプト

### メディアタイプ

kijuku-dbは3種類のメディアタイプをサポートしています：

- **comic**: コミック、漫画
- **video**: 動画、映画
- **music**: 音楽、オーディオ

### データモデル

主要なデータ構造：

- **Media**: メディア本体の情報（タイトル、作者、パスなど）
- **Tag**: タグ（分類、カテゴリ）
- **MediaAttribute**: 追加属性（EAVモデルによる拡張可能な属性）

### 基本的な操作フロー

1. **データベースの初期化**
   ```
   DB接続 → マイグレーション実行
   ```

2. **メディアの登録**
   ```
   メディア作成 → タグ追加（任意） → 追加属性設定（任意）
   ```

3. **メディアの検索**
   ```
   フィルタ条件設定 → 検索実行 → 結果取得
   ```

4. **メディアの更新・削除**
   ```
   メディアID取得 → 更新/削除実行
   ```

## データベースファイル

kijuku-dbはSQLiteをバックエンドとして使用します。

**ファイル配置の推奨:**
- **NAS/サーバー上**: データベースが配置されるマシン上で直接SDKを実行
- **リモートアクセス**: TypeScript SDKのリモート機能を使用してSSH経由でアクセス

**注意事項:**
- ネットワークファイルシステム越しのSQLiteアクセスは非推奨（データ破損リスク）
- リモートアクセスが必要な場合は、TypeScript SDKのRemoteKijukuDBを使用してください
